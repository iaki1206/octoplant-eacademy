Operations Chapter 16

OT Backup Tests & Recovery Procedures

Learn the standard operating procedures for conducting regular OT backup tests, ensuring recovery readiness, and documenting the process in SAP.

1. Objective and Purpose

For many components of our production systems, we create backups that are archived in our central backup management tool (Octoplant). The primary purpose of this process is to ensure regular training of the recovery procedure and to verify that the available backups are functional and can be successfully restored in an emergency.

ℹ️
Scope of Application
This procedure applies initially only to the sites of Dorsten, Hildesheim, and Knetzgau.

2. Preparation of the Recovery Tests

The recovery tests are intended to ensure that, in the event of a disruption—for example, a PLC failure—we can quickly restore the system to an operational state. The goal is not to pose a sustained risk to production or cause major downtime, as this would contradict the very purpose of the backup strategy.

2.1 Personnel Requirements

The personnel performing the recovery tests must possess the necessary qualifications to carry out the tests. They must also be familiar with troubleshooting the respective components and have experience operating the associated machines.

2.2 Component Requirements

Recovery tests should only be performed on components for which spare parts are available on-site in the event of a defect. Furthermore, the site must have full access permissions. For example, in the case of a Siemens PLC, any general or safety passwords must be known and available to the personnel conducting the test.

2.3 Machine Availability Requirements

A time window of at least two hours must be planned for performing the recovery tests, even though the process will typically take significantly less time. In practice, this means that tests should only be conducted during maintenance shifts or sufficiently long planned system downtimes.

3. Execution of the Recovery Tests

The execution depends heavily on the specific component and therefore cannot be defined in detail for all components. Based on the personnel requirements defined above, the general procedure should already be known to the employee performing the test.

It is important that different types of components (e.g., S7‑300, S7‑1500, frequency converters from various systems) are tested regularly to ensure broad coverage of the plant's technology stack.

CRITICAL STEP

Create a Live Backup First

Before beginning any work, a backup must always be created from the live system and stored securely. This ensures that, in case any issues arise during the test, the machine can be restored to its exact previous state immediately.

The decision regarding which backup version to use for the test lies with the performing person. Possible options include:

  • The latest available backup
  • A backup from a specific date
  • An older backup specifically chosen for testing purposes
⚠️
Post-Test Verification
After completing the test, it must be ensured that the component and, if applicable, the machine have been restored to a fully operational state. Furthermore, the startup of the machine or component must be checked once again to verify proper functioning.

4. Documentation in SAP

The execution of the recovery test must be documented thoroughly. The documentation must include:

  • Date of the test
  • Name of the person performing the test
  • Specific component tested
  • Backup version used
  • Any anomalies or issues encountered

For this purpose, a monthly maintenance order must be created in SAP by the site, through which the documentation is completed. The maintenance order must be created at a one‑month interval and should be prepared in a manner similar to the examples shown below.

Summary: OT Backup Test Workflow

Phase Action Requirements / Details
1. Preparation Schedule test window Minimum 2 hours during maintenance shift or planned downtime.
2. Verification Check prerequisites Qualified personnel, spare parts available, full access/passwords known.
3. Safety Create live backup Mandatory: Create and store a backup of the current live system before proceeding.
4. Execution Perform recovery Restore selected backup version to the component.
5. Validation Verify operation Ensure component/machine is fully operational and check startup sequence.
6. Documentation Log in SAP Record date, name, component, version, and anomalies in the monthly SAP maintenance order.
